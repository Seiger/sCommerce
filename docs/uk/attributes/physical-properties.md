# Фізичні параметри товару

Вага та габарити зберігаються як числові атрибути `weight`, `width`, `height`,
`length`, `volume`. Міграція створює відсутні визначення, переклади та прив'язку
до категорії `0`. На новому встановленні статичних колонок немає.

На старих встановленнях колонки залишаються. Міграція не змінює їхні дані.
При збереженні моделі товару кожне додатне ціле значення статичної колонки
переноситься у відповідний атрибут як грами, міліметри або мілілітри,
перезаписуючи його попереднє значення, а колонка обнуляється. Перенесення
й обнулення виконуються в одній транзакції. Нульова колонка не перезаписує
атрибут при наступних збереженнях. Дробове легасі-значення не має відомої
одиниці. Воно залишається в колонці й показується у формі товару для ручного
введення, якщо явне значення того самого вимірювання його не замінює.

Редагування відбувається у вкладці атрибутів. Біля полів фізичних атрибутів
форма менеджера показує одиницю (г, мм, мл). Значення — цілі числа: вага
в грамах, ширина, висота й довжина в міліметрах, об'єм у мілілітрах.
Запис через модель: `$product->setPhysicalValue('weight', 1000)->save()` (1 кг).
Дробові або від'ємні значення відхиляються з помилкою.
`$product->physicalValues()` повертає цілі числа й дає явну помилку
для значення, яке неможливо прочитати. Хелпер `$product->attribute('weight')`
повертає ціле число у `value` та підпис з одиницею, наприклад `1kg`, у `label`.
Прямого перенаправлення `$product->weight` на атрибут немає, старі колонки
не використовуються як резерв при читанні. Порожнє значення фізичного атрибута
у формі означає нуль.

Копіювання товару переносить фізичні параметри звичайним копіюванням атрибутів,
без статичних полів. Перед дублюванням менеджер зберігає джерельний товар, щоб перенести
його додатні колонки. CSV використовує атрибути; старі вхідні ключі також
перетворюються на явний запис атрибута. Кошик і швидке замовлення використовують
`$product->physicalPayload()`. Вимірювання, яке неможливо прочитати, не потрапляє
в рядок і записується в лог, а покупка не зривається. Інтеграції доставки ніколи
не отримують вигаданого числа.

Масові SQL-записи, `insert`, `upsert`, `query()->update` не викликають збереження
моделі. Зовнішні імпортери потрібно перевести на атрибути. Повна заміна атрибутів
має включати фізичні параметри. Дублікати alias або непідтримувані типи зупиняють
міграцію. Повернення міграції не видаляє дані атрибутів.

Перерахунок кількості у вагу й мінімум замовлення реалізуються окремо.

## Наявні атрибути-списки

Міграція не змінює вручну заданий тип атрибута. Тип `3` залишається списком;
ID атрибутів, варіанти, їхні ID, зв'язки й поточний вибір товарів не переписуються.
Тільки відсутні атрибути створюються як числові (`0`).

У варіанті списку `alias` містить число, а `base` — підпис для показу,
наприклад alias `1000` з підписом `1kg`. ID варіанта й підпис ніколи
не інтерпретуються як вимірювання. Варіант, alias якого не є цілим числом,
дає явну помилку в `physicalValues()`, а не вигадане число.

При записі значення в атрибут-список повторно використовується варіант
із таким alias. Якщо його немає, створюється новий варіант: alias — число,
підпис — з одиницею (`250g`, `1kg`, `25.5cm`, `500ml`). Тип атрибута ніколи
не змінюється.
