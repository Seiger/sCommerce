# Фізичні параметри товару

Вага та габарити зберігаються як числові атрибути `weight`, `width`, `height`,
`length`, `volume`. Міграція створює відсутні визначення, переклади та прив'язку
до категорії `0`. На новому встановленні статичних колонок немає.

На старих встановленнях колонки залишаються. Міграція не змінює їхні дані.
При збереженні моделі товару кожне наявне додатне значення статичної колонки
переноситься у відповідний атрибут, перезаписуючи його попереднє значення,
а колонка обнуляється. Перенесення й обнулення виконуються в одній транзакції.
Нульова колонка не перезаписує атрибут при наступних збереженнях.

Редагування відбувається у вкладці атрибутів. Читання для кошика й доставки:
`$product->physicalValues()`; запис через модель:
`$product->setPhysicalValue('weight', '0.0125')->save()`.
Прямого перенаправлення `$product->weight` на атрибут немає, старі колонки
не використовуються як резерв при читанні. Значення зберігають одиниці магазину
та чотири десяткові знаки. Порожнє значення фізичного атрибута у формі означає нуль.

Копіювання товару переносить фізичні параметри звичайним копіюванням атрибутів,
без статичних полів. Перед дублюванням менеджер зберігає джерельний товар, щоб перенести
його додатні колонки. CSV використовує атрибути; старі вхідні ключі також
перетворюються на явний запис атрибута. Кошик і швидке замовлення включають
числові вимірювання з атрибутів для інтеграцій доставки.

Масові SQL-записи, `insert`, `upsert`, `query()->update` не викликають збереження
моделі. Зовнішні імпортери потрібно перевести на атрибути. Повна заміна атрибутів
має включати фізичні параметри. Дублікати alias або непідтримувані типи зупиняють
міграцію. Повернення міграції не видаляє дані атрибутів.

Перерахунок кількості у вагу й мінімум замовлення реалізуються окремо.

## Наявні атрибути-списки

Міграція не змінює вручну заданий тип атрибута. Тип `3` залишається списком;
ID атрибутів, варіанти, їхні ID, зв'язки й поточний вибір товарів не переписуються.
Тільки відсутні атрибути створюються як числові (`0`).

Для розрахунків фізичних параметрів код читає числовий `base` вибраного варіанта
(або простий числовий alias, якщо `base` порожнє). ID варіанта й slug ніколи
не інтерпретуються як вага чи габарит. Нечислове вибране значення дає явну помилку,
а не вигадане число.

При збереженні додатного легасі-значення в атрибут-список вибирається варіант із
відповідним числовим значенням. Якщо варіанта немає, створюється новий числовий
варіант. Кілька однакових числових варіантів вважаються неоднозначністю і зупиняють
запис без обнулення легасі-колонки. Тип атрибута ніколи не змінюється.
