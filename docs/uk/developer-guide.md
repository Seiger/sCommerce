# Динамічне ціноутворення

`sPriceResolver` — єдина точка отримання `price`, `oldPrice`, `priceAsFloat` і `oldPriceAsFloat` у sCommerce. Її використовують модель товару, каталог, кошик і checkout.

Якщо клас sPricing доступний, resolver передає йому контекст поточного користувача. Якщо пакет відсутній або не повернув придатну ціну, sCommerce використовує історичне правило `price_special` / `price_regular`. Це зберігає сумісність для наявних магазинів.

Кешована сторінка або модель містить нейтральні дані товару. Контекстну ціну resolver накладає в межах поточного запиту, тому ціна одного користувача не потрапляє до іншого через спільний кеш.

# Безпечне відновлення вкладок менеджера

Провайдер реєструє дозволені сторінки перегляду в `cms.manager_tab_restore.modules.<module-id>`: дашборд, список замовлень і деталі замовлення. Менеджер із підтримкою цього контракту відновлює їх з актуальним CSRF-токеном сесії, не зберігаючи токен у стані вкладок.

Ключ `<module-id>` береться з результату `registerModule()` під час реєстрації модуля. Не обчислюй його повторно через перекладач у `boot()`: локаль перекладача на цьому етапі може відрізнятися від мови менеджера, через що відновлення вкладки відхилить її ID. Якщо модуль не зареєстровано, запис для відновлення не створюється.

Цей список не надає прав доступу та не вимикає перевірку CSRF для `a=112`. Дії збереження, видалення та інші зміни даних не можна додавати до списку автоматичного відновлення. Нові параметри й обробники, включно з хуками розширень, потребують перевірки перед реєстрацією. Менеджери без підтримки контракту просто не використовують цю конфігурацію.
